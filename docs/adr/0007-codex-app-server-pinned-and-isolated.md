# The Codex app-server is pinned by `codex.version`, and only `@agentic/codex-harness` speaks its protocol

`codex.version` is the single source of truth for the Codex runtime: the deploy package locks that exact version, the protocol bindings are generated by the pinned binary and never hand-edited, and `@agentic/codex-harness` is the only application package allowed to speak its JSON-RPC protocol. The binary ships only in the full API image, never in Factory control, workload, CodeAct or candidate images, and production callers allow-list child environment variables and route model credentials through the platform gateway rather than inheriting host secrets. An unpinned engine or a second protocol client would make OntoCode builds non-reproducible, and an inherited environment would leak provider credentials into generated code paths. Upgrading means moving the pin and the deploy package together, regenerating, inspecting the diff, then running the protocol check and the harness verification.
