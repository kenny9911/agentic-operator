## Implementation map

- **Contracts/core:** `packages/contracts/src/skill*.ts` and `packages/skills` own portable files, real YAML parsing, bounded ZIPs, byte digests, immutable sessions, strict tool schemas, active guidance and Creator proposals. Legacy filesystem Skills are captured safely as fixed bundles. All nine checked-in Tenant Skills remain compatible.
- **Library:** migrations 0080–0081, `skill-library-store.ts`, `skill-library.ts` and `/v1/skills` own tenant-scoped drafts/revisions/publications, permissions, audit, history, restoration and archives. Shared ownership is resolved by the server to `__system`; users cannot supply an owner. Publication uses revision compare-and-swap and immutable version rows.
- **Builder and comparisons:** `skill-creator.ts`, `skill-evaluation.ts` and portal Skills components use the existing Gateway. Generated assumptions/checks are explicitly unexecuted. Comparisons contain two real responses tied to a source digest, with separate human review. There are no model tools, scripts or external services in comparison runs.
- **Runtime:** `skill-runtime.ts` captures exact sources, versions, activation selections and trusted lineage. Manifest checkpoints survive memoized Actions and reconstruct active guidance; BaseAgent receives a host-created session after its real run row exists. CodeAct Skills calls remain host RPC, with child catalogs restricted to the inherited scope. Raw provider reasoning stays in transport; only deliberate summaries are persisted.
- **Scripts:** `packages/skill-runner`, its isolated image, `skill-script-runtime.ts`, migration 0082 and the separate `skills.run_script` business Tool enforce both host capability and Agent allowlists. Immutable root reservations count interrupted/retried attempts; descendants share the same ceiling. Evidence and binary artifacts are persisted. Missing configuration disables execution.
- **Codex:** the pinned harness materializes authorized bundles and rejects unexpected native discovery. `codex-skill-runtime.ts` reads the frozen Run catalog before file writes/discovery and verifies it again before explicit inputs. The repository's selectable production Codex execution adapter was already disabled pending its separate gateway/supervision work; this feature does not claim to enable that unfinished execution product.
- **UI/help:** the Skills sidebar, file editor, history, version controls, import/export, AI creation/revision, comparisons, Workflow/Agent bindings and English/Chinese help use the existing portal. Test Lab exposes Skill activation/read receipts separately from model output.

## Product defaults and deployment boundary

The implementation uses Tenant libraries plus a superadmin-managed shared library, editable drafts and immutable published versions. These are implementation assumptions made under the requested task, not answers inferred from the earlier unanswered preference questions. They remain reviewable without weakening Tenant isolation or historical version identity.

Local runner and CodeAct candidate images were built and verified. Production deployments must deliberately install/approve their images, configure tenant script capability and use the rebuilt candidate bootstrap. No production allowlist was silently changed. The execution daemon's deployment owns crash reconciliation; unknown interrupted outcomes are not reported as success. Test Lab cannot grant script capability or bypass business Tool policy.

HEAD and working-copy registry code match; a minimal no-DB/no-model probe reproduces the overwrite. This work does not claim the full API suite is entirely green or change that registry behavior.

Final checks also passed: full production build, 29-package typecheck, lint, generated Workflow schema drift check, pinned Codex protocol drift check, local documentation links and whitespace validation. A host `CODEX_CLI_PATH` override initially pointed at a newer CLI; the protocol check was rerun successfully with the installed pinned binary, without changing the host setting.
